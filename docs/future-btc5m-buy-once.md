# Future BTC 5 分钟：准备完成后自动买入

脚本：[buy_once.js](../scripts/future-btc5m-extension/buy_once.js)。扩展 0.4.0 起，manifest 在 `content.js` 之后加载它，它跟随项目页的“自动准备票据”开关：开关开启时，票据准备好（READY）后自动点击一次 Future 买入；开关关闭时不点击。用户已确认，这改变了该开关原来“最终买入由你完成”的含义。

本次只完成代码和本地测试，没有在真实 Future 页面点击买入。生产页面的订单列表不会因此生成平台订单回执；点击尝试、订单提交和实际成交要分别核对。

## 工作方式

- `content.js` 每秒读取一次准备状态，并在本轮准备之前调用 `createAutoBuyer().sync(enabled)`。开关开启时保持一个实盘监控；监控结束（已点击或受阻）后立即换上新的监控。开关关闭时停止监控。读取不到有效准备状态时，既不启动也不停止监控，只显示当前状态。
- 监控每 500 毫秒读取一次准备状态，只接受**监控开始之后**新生成的本轮 READY。之后核对真实的美元市价买入票据：金额必须恰为 `1`，当前选中方向、READY 方向和涨/跌按钮中数字较大的一方必须一致。检查通过后，点击票据内唯一的“买入 涨”或“买入 跌”。
- 每轮最多点击一次。点击后换上的新监控，开始时间晚于本轮 READY 的生成时间，所以不会追买。本地占用键 `polyhermes.future-btc5m.buy-once` 也会拒绝同一轮的再次点击。如果开启开关时本轮 READY 已经生成，从下一轮开始买。
- 点击结果记为 `PLATFORM_RESULT_UNKNOWN`。脚本不处理额外确认、钱包签名、成交回执或失败补单。

## 使用步骤

1. 在 `chrome://extensions` 对 **PolyHermes Future BTC 5m 助手**点击“重新加载”，确认版本为 0.4.0，再刷新 Future 页面。权限没有新增。
2. 保持 Mac 助手、私有隧道和已登录的 Future BTC 5 分钟页面运行。
3. 在项目页开启“自动准备票据”。面板最后一行“自动买入”的含义：
   - `已开启，新票据准备好后点击一次买入（每轮最多一次）`：正在监控。
   - `最近：已点击“买入 涨/跌” $1（btc-updown-5m-…）`：已尝试点击，成交以 Future 订单为准。
   - `最近：未点击（原因）`：该轮检查未通过，不重试。
   - `当前关闭，不会点击`、`暂不点击`、`无法启动` 或 `脚本未加载`：没有监控在运行。
4. 停止自动买入：在项目页关闭“自动准备票据”。面板读到关闭状态后停止监控；监控本身也只接受 `enabled=true` 的 READY。

已经发生的点击尝试不会被撤销。跨页面重载的同轮占用不会自动清除；不要删除占用记录来重试结果不确定的订单。

## 核对与去重

- 只接受 `PREPARE_ONLY`、`USER_REQUEST`、schema2 的当前 READY；当前 intent 必须为空，准备回执必须确认本轮方向与 $1。
- 保留现有入场窗口：本轮第 60 秒至第 80 秒之前。原始价格和按钮快照在认领、READY 和当前检查时都不能超过 5 秒；读取状态不会延长原始许可。
- 涨/跌数字相同、缺失、较大一方改变、金额改变、页面标题仍是旧轮次、按钮禁用或有歧义，一律拒绝。脚本不重新填写金额、不切换方向，也不会默认买涨。
- 实盘必须有 Web Locks。持锁后再读取一次 READY 并检查当前 DOM，然后先写入唯一的本地占用键。存储失败就停止，不接触其它存储键或登录资料。
- 写入占用后，在不含 `await` 的最后阶段再次核对时效、票据和同一个已连接按钮，避免存储变慢或页面变化导致过期点击。此阶段的拒绝显示为“最终核对失败”，已写入的占用仍保留，既不点击，也不自动补试。
- 同一浏览器配置中，同一 Future origin 下的实例由 Web Lock 和 localStorage 去重；不同设备、不同浏览器配置或不同 origin 之间不保证互斥。点击抛出异常也视为已占用，不重试，也不认定成交。

扩展上下文中仍保留 `FutureBtc5mBuyOnce.start()` / `status()` / `stop()`，可在控制台诊断；默认是模拟模式，不点击，与自动买入共用同一个 Web Lock 和占用键。现在不需要再手动粘贴脚本，重复加载会报 `WATCHER_ALREADY_LOADED`。
