# ETH / SOL 前瞻纸上验证

固定启用 ETH G1、ETH G2、SOL G1。每笔模拟本金$1。新币种由独立、无钱包/凭据/浏览器挂载的只读公共行情容器采集，不接入 BTC 的票据、控制、策略选择或订单 API。

保留反同币1小时、R1<=4.16bp/分钟、150–170秒入场、热门60–97¢、$1深度模拟及准备价±5¢门槛。G1为abs(trend60Bp)>=15；ETH G2为abs(trend60Bp)<5或>=15。趋势和波动复用生产函数。仅从启用后开始，无历史回填，每币每轮唯一基线，ETH的两个规则对同一基线作独立$1模拟，SOL不计算G2。

报价源为公开CLOB book，与BTC旧纸上验证的Future按钮报价口径不同。没有独立Future页面报价，3¢跨平台核对未验证，界面必须明确说明。只模拟可读深度，不宣称实际成交。采用平台最终payout并逐价扣Polymarket费用；不将待结算计作0收益，不假设Future额外费率。SQLite独立持久账本幂等，进程重启不会重记一轮。BTC旧纸上结果与原控制设置保持原样。

采集器固定只允许Gamma events、CLOB book、Binance klines和Data API resolutions的HTTPS GET，拒绝跳转及任意地址，无交易SDK。HTTP仅有GET /status与/health，均无状态变更。Docker私有网络内监听8777，无宿主端口，非root、只读根目录、丢弃全部capability，仅挂载自己的纸上状态目录，退出自动重启。

项目后端通过已认证的POST /api/future-btc5m/paper/observe/status读取该容器的固定/status，不转发JWT/Cookie/交易控制头。数据不可用或心跳超过30秒时页面隐藏当前指标并提示待核实。页面显示ETH两组与SOL一组的待结算/已结算、胜率、含市场费纸面盈亏、过滤赢家/亏单和最近20个基线影子单。

部署使用独立Compose文件；首次创建状态目录并归属UID10001，再构建/启动。后端及前端按现有受控发布流程部署。需要验证采集心跳、自然入场轮次、账本重启幂等、请求只读、应用认证、页面状态，严禁通过真实买入验收。
