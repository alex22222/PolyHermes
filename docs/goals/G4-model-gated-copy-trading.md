# G4：人工控制 Leader 的模型化跟单决策

## 目标身份

- 优先级：P0，项目第一优先级
- 状态：ACTIVE
- 执行方式：Loop Engineering
- 状态文件：`G4_LOOP_STATE.md`

## 业务目标

在 Leader、领域、币种、账户、资金上限和启停均由人工控制的前提下，引入分领域模型作为 BUY 决策闸门，提高风险调整后收益和资金利用率。

模型不是交易执行器。所有建议必须先经过 G3 已上线的人工暂停与组合硬风控，模型不得新增 Leader、放宽阈值、直接调用 Bridge 或绕过 SELL 持仓与幂等校验。

## 决策合同

- `SKIP`：拒绝本次 BUY。
- `WATCH`：记录观察，不执行。
- `BUY_SMALL`：建议使用人工配置上限内的小额档。
- `BUY_NORMAL`：建议使用人工配置的正常档。

初始阶段全部为 Shadow 建议，不改变交易。任何实盘权限升级都必须单独由人工确认。

## 完成条件

1. 决策候选、模型输入、模型版本、建议、实际执行、跳过原因和结算结果可完整关联。
2. Crypto、金融、政治使用独立特征与评估，不用单一文本模型硬套全部领域。
3. 训练、时间切分回测、校准和数据泄漏检查可重复运行。
4. Shadow 报告覆盖收益、最大回撤、命中率、过滤率、资金占用和各决策档表现。
5. 模型不可用或输入不完整时安全降级，不影响 G3 人工暂停和硬风控。
6. 第一阶段实盘能力只能拒绝 BUY；金额选择需再次人工批准。
7. 自动 SELL 仅限预定义风险场景并需独立人工批准，普通模型建议不能直接卖出。
8. 后端、前端、Bridge 测试和运行健康检查通过，所有权限变化可审计和回滚。

## 阶段计划

### Phase 1：标签与数据合同

- 审计现有信号、过滤、执行、FAILED、未结算和结算数据。
- 建立稳定的 candidate/decision/execution/settlement 关联 ID。
- 区分“模型跳过”“原有规则过滤”“执行失败”和“未收到执行结果”。

### Phase 2：确定性基线

- 用现有价格、流动性、Leader、市场时间、暴露和风控特征建立无模型基线。
- 分领域计算可复制性和预期价值，作为模型必须超越的基准。

### Phase 3：离线模型与验证

- Crypto、金融、政治分别训练和校准。
- 使用严格时间切分，检查标签延迟、未来信息和同事件泄漏。
- 输出可解释特征贡献与置信度，不只输出分类。

### Phase 4：Shadow 决策闸门

- 在线生成四档建议并保存完整输入快照。
- 不改变现有交易，只比较反事实结果和真实结果。
- 模型故障时记录降级原因，不阻断现有安全路径。

### Phase 5：拒绝权限

- Shadow 达标并经人工批准后，只开放 `SKIP/WATCH` 对 BUY 的拒绝能力。
- G3 风控先执行；模型只能更保守，不能覆盖硬拒绝。

### Phase 6：金额与预定义退出

- 再次人工批准后才允许 `BUY_SMALL/BUY_NORMAL` 选择人工配置档位。
- 自动 SELL 仅在预定义紧急风险场景中单独试点，普通退出仍逐笔确认。

## 安全边界

- 人工控制 Leader、领域、币种、账户、资金上限和启停。
- 模型输出不能扩大人工配置金额。
- G3 人工暂停和硬风控优先于模型且不可被覆盖。
- 模型服务不可用时禁止新增模型权限，不得静默放行已启用的模型硬拒绝逻辑。
- 未经人工批准，不启用拒绝、金额选择或自动 SELL。
